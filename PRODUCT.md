# NEXUS
<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Buildless HTML/CSS/JavaScript ES modules and a Node.js standard-library local server. Zero package installation, no database/API keys. This is an implementation choice for a portable hackathon prototype, not a user-mandated stack.

## Users and purpose
Township managers inspect resource opportunities, test economics and coordinate facilities, landscape contractors and residents. Resident BioLoop contributions replenish future material inventory. Demonstrate Sense → Optimise → Mobilise → Verify through one Water + BioLoop intervention.

## Operating context
Sime Darby Property hackathon, PLANET focus. The supplied clarification permits public information, research and clearly stated synthetic data; proprietary datasets will not be supplied. Broader Malaysian township/community applicability is required. The user's current priority is an identifiable logo, realistic defensible data, and a sophisticated interactive application rather than a static page. English product copy is an implementation assumption.

## Capabilities and constraints
Four connected views: overview with draggable schematic map and model timeline; Action studio with allocation/effect/transport sensitivity and receipts; resident wallet and staff collection desk; reconciled impact ledger and evidence export. Default Live outlook uses current public weather and fourteen forecast rain/ET₀ days, polling every minute while visible. Draft demand/economics track the source; approval freezes its inputs. Three historical scenarios remain available: original dry reference, derived seasonal scenario and storm stress-test. Human approval cannot bypass hard constraints. Inventory reservations, raw/processed separation, once-only staff-confirmed credits, cancellation and interrupted-work handling are enforced by the engine. Browser storage persists each scenario independently.

## Evidence on hand
Retained Open-Meteo / ERA5 July1–14 2025 rainfall and ET₀ near Shah Alam; official MET forecast API for Petaling with original dates and fallback; published Air Selangor tariff; FAO indicative water-balance/efficiency guidance. These ground a hypothetical site model. There are no proprietary meter feeds, real permissions, lab results or measured outcomes. Area, stock, costs, mulch effect, yield, processing days, demo identities and post-intervention readings remain declared assumptions/simulation. New collection replenishes future stock; the intervention uses existing ready mulch. MET descriptions remain context. Live outlook separately uses actual numeric Open-Meteo forecasts, clearly labelled current model / forecast rather than onsite sensor observations. Public data does not create real device stock or a live irrigation controller.

## Principles
Make the next operational action clear. Let parameter changes reveal trade-offs, including negative economics. Show missing evidence and block unsafe plans. Separate model estimates from measured outcomes. Never add unlike units or imply carbon conversion without evidence. The event trail is editable browser storage, not an immutable audit service. Respect keyboard navigation and reduced-motion preferences. No production auth, real dispatch, payments, sensor integration or LLM decision service is claimed.

## Readability and interaction refinement

Identity is removed from product navigation and the public brand page is removed, while logo source SVGs remain. Ordinary prose uses 16px with 12–14px compact labels and larger headings. Plan comparison presets, disclosure-preserving copy, per-day playback controls, asset camera focus and evidence-class filtering support actual operator tasks.
